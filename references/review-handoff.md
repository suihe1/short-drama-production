# 把审批交到用户手里

本规范落实 `pipeline.md` 已有的人工审批门，不新增逐工具调用确认。适用于总控调用专业 skill 后的交付；总控负责收尾，不能假定专业 skill 会自行打开报告或提出审批。

## 何时展示，展示什么

| 到达节点 | 主动展示 | 用户检查重点 | 确认后推进 |
|---|---|---|---|
| 项目范围 | 对话中的需求摘要即可 | 集数、时长、画幅与改编幅度 | 大纲 |
| 大纲完成 | 大纲评审 HTML；无 HTML 时展示 Markdown | 删合支线/角色、爆点和结尾 | 角色和美术 |
| 角色/美术完成 | 角色、场景/道具报告及实际候选图；声音需可播放试听 | 人物身份、画风、场景功能与声音 | 当前批剧本与导演 |
| 每批剧本完成 | 剧本报告，定位本批集数 | 行动和台词、时长、钩子 | 导演设计 |
| 导演方案完成 | 导演镜头表；已有可视报告就打开 | 调度、信息展示、节奏 | 技术分镜 |
| 技术分镜/参考图完成 | 故事板 HTML，定位当前段 | 画面顺序、姿态和手别、关键信息可读性 | 冻结参考包、准备样片 |
| 样片生成前 | 具体任务及成本摘要 | 提供方、段号、数量/秒数、费用或上限 | 仅在授权范围内提交 |
| 样片完成 | 故事板的镜头明细与视频对照，或直接播放样片 | 外观和声音、主体/摄影机运动、信息与节奏 | 准备批量计划；未授权批量则另确认成本与范围 |
| 粗剪/QC 完成 | 可播放工作版与带时间码的问题单 | 叙事连续性、声画、未解决问题 | 返工或交付；发布按授权范围执行 |

这是交接顺序，不要求一次打开全项目所有 HTML。角色与美术等可同批审阅，保持具体范围。纯状态查询只读列出当前待审项与已存在链接，不借机推进创作、生成新报告或索取额外授权。

## Agent 的交接动作

1. 先执行适用质量门、修复可自行解决的问题。缺图时明示“仅审镜头方案，图片未验收”；演示页标明“示例”，不能当作实际项目的审批对象。
2. 为当前版本生成或选择报告，核对它确实来自当前制品和依赖。旧 HTML 是快照，内容变化后生成新文件名，保留旧报告中的会话与笔记。已有批准仍覆盖当前哈希时不重复审批。
3. 在具备面板/浏览器打开能力时主动打开报告，再给可点击的绝对路径链接。工具仅返回 queued 时说“已请求打开”，不能声称用户已看到。无法自动打开时给链接及“点击链接，用浏览器打开”的一句说明；不用让用户寻找文件、安装开发环境或运行 CLI。
4. 在对话中交付：当前阶段和集/段范围、版本、最多三个检查重点、尚存缺口、确认后的具体动作。用一句明确问题收取结论，例如：“请确认当前 E01-01 的镜头顺序与参考图是否通过，还是需要按镜号修改？”不要仅说“可以看看”“需要时打开”。依据当前对话的工具规则提出问题；审批问题不使用仅支持可选偏好的工具。
5. 确认前完成所有不依赖该决定的准备，不把用户确认当作开始整理资料的前置步骤。到达必须用户判断的门时，解释来源是本 skill 的 `pipeline.md` 人工审批门（引用相应阶段），并链接实际读取的 `SKILL.md`；不要增加假想风险或额外确认轮次。

可用交付示例（将占位内容替换为真实路径与范围）：

> E01-01 分镜已准备好，已请求打开当前报告：[查看故事板](绝对路径)。先从左到右看画面顺序，重点检查第 2 镜手机是否看得清、第 3 镜持物手是否连续。通过后我会整理样片任务和费用供确认。你可以回复“通过 E01-01 分镜”，或“修改 E01-01 第 2 镜：手机再近一点”。

## 页面怎么用，结论如何回到 Agent

- 分镜评审：选择当前片段，从左到右看多格图；点某一格检查拍摄要求。生成样片后切到“镜头明细与视频对照”观看完整片段。规划节奏预览不等于实际视频效果。
- 少量反馈直接在对话中说集/段/镜号和修改点，无须为了回复而使用每个导出按钮。多条反馈可以填写笔记，下载 JSON 后在对话中提供本地文件路径；agent 读取用户指定文件并归纳修改范围。下载本身不会把文件传给 agent。
- 保存编辑会话用于下次恢复笔记与替换图片；导出审阅图用于分享；模型参考图和映射仅在准备参考包时需要。替换图仍需正式登记到项目并按当前内容验收，页面编辑不自动更改源资产。
- 页面中的“我已逐格检查”只解锁模型参考图导出，不改变 `production.json`，也不授权任何生成费用。不要让用户误以为点过这个框就已经告知 agent。
- 得到结论后复核用户所指范围及当前文件/依赖哈希。内容发生变化就指出差异、呈现新版本；对已经明确批准的同一版本不再询问。收到反馈就修复后复验并交付差异，不能把有修改要求的回复记为批准。
- 用户确认时用已有 `approve` / `voice-approve` / `job-approve` 路径记录实际范围和原意，不伪造用户确认。不把“继续开发功能”解释为短剧内容通过，也不把内容通过解释为付费、重试、批量或发布授权。
- 会话恢复后先说明尚未决策的节点和对应链接；若同一版本已提出问题且仍在等待，不重复轰炸，继续不依赖该决定的工作。
