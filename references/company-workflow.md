# 制作职责、阶段交付与变更

本项目采用“开发 → 预制 → 生成与选片 → 剪辑 → 画面锁定 → 声音/调色/字幕 → 交付”的顺序。借用专业影视制作的职责和交接方式，不增加与 AI 制作无关的实拍行政表单。阶段状态仍由 production.json 管理；本文件不新增运行时 schema。

## 职责与唯一内容源

| 负责人 / skill | 对什么负责 | 输入与交付边界 |
|---|---|---|
| 制片总控 / short-drama-production | 范围、产能预算、阶段状态、汇总反馈、任务执行和最终交付 | 汇总链接/哈希/决策，不重写各部门正文；统一向用户提出当前需要的判断 |
| 改编 / novel-outline | 故事主线、人物去留、分集因果和类型节奏 | 先定方向，再细化分集；原著角色扫描不等于批准全部角色投产 |
| 角色 / novel-characters | 保留人物的身份、视觉与声线设计 | 先主角样张，再本批需要的角色；声线描述不等于声音母版 |
| 美术 / novel-art | 空间功能、视觉设计、叙事道具和状态 | 概念版支持初稿，剧本拆解后完善本批资产；无人母本不等于成片无人 |
| 编剧 / novel-script | 场内行动、对白、人物知情范围和跨集因果 | 剧本是剧情事实源；时长先估算再围读，不让模型经验替代写戏 |
| 导演 / short-drama-director | 表演、调度、观看策略、覆盖和可剪性 | 先设计镜头再适配生成包；继承项目画幅，不自动另立规格 |
| 技术分镜 / novel-storyboard 或导演桥接 | 生成段、参考职责、逐镜时间、提示词映射 | 两条路线择一，保留导演来源与差异；不重复改戏或重切镜头 |
| 模型提示词 / h3-prompt-writing | 所选模式的官方结构、标签、时间标记 | 消费已确定镜头和参考资产，不负责内容审批或 API 执行 |
| 场记与剪辑 / 总控协调 | 连续性账、镜头覆盖、选片、接点、锁画与返工 | 复用导演 continuity、beatRefs、任务 ID 和 QC，不另造一份剧情真相 |

没有独立岗位时由总控承担协调；这些职责名称不要求额外创建 agent 或 skill。

## 阶段出口

1. **开发通过**：需求与范围清楚，改编方向和人物去留已确认。资产预算计入设计、生成、筛选、连续性维护与后期，不能按“换景免费”无限铺设。
2. **本批剧本可进入导演设计**：因果、人物知情与台词成立，做过围读或明确标为公式估时；所需资产有清单。概念美术可先支持写作，不要求全剧所有图已完成。
3. **本批预制可投产**：导演方案、关键参考与声音路线已确认；先用故事板/临时音轨验证信息顺序，无法播放动态预演时明确只做了静态审阅。完成当前模式的最终校验与任务预检，再按既有成本授权范围执行。
4. **生成完成不等于入选**：先下载并核对任务和文件，再看表演、连续性和接点。每个片段选择明确版本；不按最新文件、文件存在或 API succeeded 自动选片。技术试拼可使用明确列出的候选，但不能称最终 QC 通过。
5. **粗剪通过后锁画**：选片、顺序、时长和必要补镜确定；交给后期的版本明确。临时声音可前置帮助剪辑，精修混音与字幕时间在画面稳定后进行。锁画后仍可改，但要列出受影响的音频、字幕、调色和导出项重新复验。
6. **交付通过**：实际可播放文件与当前批准版本一致，完成叙事/表演人工审片和媒体技术检查。检测工具缺失或未看片均为未验证，不能用结构 PASS 替代。

完整导演包并非每个简单独立分镜任务的强制前置；缺导演包时可由分镜承担基础导演判断并标注来源。整部项目则由总控选择路线，避免两个 skill 同时改同一镜头。

## 不制造环形依赖

概念美术与剧本初稿允许往返。若要追踪初稿催生的新资产，用独立版本表达：script-draft → art-production → script-locked；不要把同一 script ID 和 art ID 互相 dependsOn。已锁定文件有实际变化才传播失效，不为更新报告时间或修改展示样式伪造创作变更。当前工具按制品文件哈希传播，尚不支持文件内部字段级影响分析。

## 统一反馈和返工

使用现有 notes / approvals / risks 与 QC 记录，必要时配一份可读修改单。每项至少说明目标 ID/版本、问题、修法负责人、受影响下游和复验结果；同一反馈只维护一次。用户意见先汇总再交部门修改，不能让每个专业 skill 各向用户索要同一确认。

已授权范围内的自检、修正与可逆准备由 agent 完成。只有剧情方向、主形象、当前批内容锁定、未覆盖的费用范围与最终交付等真实节点收取用户判断。展示方式统一读取 review-handoff.md。用户已批准的当前版本不重复审批，新增费用和变更范围不能从无关的“继续”推导。

## 依据与适配范围

本职责划分参考 ScreenSkills 对[编审](https://www.screenskills.com/job-profiles/browse/film-and-tv-drama/development-film-and-tv-drama-job-profiles/script-editor-film-and-tv-drama/)、[美术指导](https://www.screenskills.com/skills-checklists/scripted-film-and-tv/art-department/production-designer-skills/)、[场记](https://www.screenskills.com/skills-checklists/scripted-film-and-tv/script-supervisor-department/script-supervisor-skills/)及[故事板](https://www.screenskills.com/job-profiles/browse/animation/pre-production/storyboard-artist/)的岗位说明：编审汇总意见并保障连续性；美术协同导演与制片；场记衔接导演与剪辑；故事板将剧本和导演意图视觉化。这里的批次、文件版本与 API 门是本 AI 项目的适配方案，不代表所有影视公司统一采用相同流程。
