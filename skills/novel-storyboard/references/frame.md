# 分镜图出图 · codex `$imagegen`

出图走 codex 内置的 `$imagegen` 系统 skill，**不需要任何 API key**——用本机 codex 登录态。**没有 codex 就整步跳过**，只交提示词，报告显示「未生成」占位，其余产出照常。

## 分镜图是什么

一个 cut 可以有一张 16:9 构图/动作规划图，**每段一个文件夹**。这张图是否成为 H3 输入由生成模式决定：I2VA/FL2VA/L2VA 只使用真实首尾帧；Ref2VA 把这些图视为候选参考，审核后按人物身份、场景拓扑、关键道具、姿态或信息内容等互补职责选择，不把每个 cut 都伪装成时间锚。

分镜图提示词 `frame` 是出候选素材前的规格；最终 `h3Prompt` 必须等候候选素材完成 QC，再按真实文件顺序生成。图片与文字冲突时，不用更强的文字去“纠正”错误图片，而是淘汰或重做图片。

## 参考图挂载（命根子）

每一格的 `-i` 清单：

1. **场景设定图**（`novel-art` 的 `images/<场景名>-sheet.png`）——必挂，环境、材质、光的唯一标准
2. **画内每个角色的设定图**（`novel-characters` 的 `images/<角色名>-sheet.png`）——有几个挂几个
3. **画内叙事道具的设定图**（`novel-art` 的 `images/<道具名>-sheet.png`）——有就挂
4. **链式参考**：某角色没有设定图时，先出他看得最清的那一格，之后所有带他的格都拿这张当身份参考（提示词明写 the SAME face, same clothes as this reference）——同集的脸不许换人。段的主分镜图也值得一直挂着，锁世界观和雾的浓度
5. **挂图按「画面里有什么」，不按「段属于哪个场」**：段在栈桥场，但画面里出现了渡船，就必须把渡船的设定图也挂上——不挂 = 每帧发明一条新船（踩过）。船、马车、宅门这类「会入画的大资产」都同理
6. **提示词必须写明人物此刻的位置状态**：已上船 / 在舱内 / 站在桥头——切镜时人物位置是连续的剧情状态，只写构图不写状态，模型会把上了船的人又画回岸上（踩过）
7. **姿态需要可见证据**：写明躺/坐/站、身体与床/椅/墙的支撑点、持物手和视线。裁掉支撑点的肩部近景不能用来证明“人物仍侧躺”。
8. **屏幕内容与屏幕载体分开**：手机插入镜头负责手、屏幕尺寸和动作；剧情关键的视频/照片另做全屏内容素材。聊天、金额、车次等精确文字使用干净可跟踪屏幕，后期合成。
9. **错误构图参考直接淘汰**：多手、左右手错、身体支撑不成立、人物朝向或轴线错误，均不得靠视频提示词“纠正”。此时采用语义资产参考：人物身份 + 空环境 + 干净道具 + 必要内容图；姿势、方位和机位只由文字调度。

提示词开头明说每张参考图的用途（which is the environment / whose face to match / which prop to match），别让模型猜。

## 调用契约

- **跑在 codex 里**：直接用 `$imagegen`，不要再 shell 出去调 `codex exec`
- **跑在 Claude Code**：shell 调本机 codex，**先探测版本最高的 binary**（旧版直接报错），探测脚本抄 `novel-characters/references/sheet.md` 的 `find_codex`
- 所有调用套 `env -u NODE_OPTIONS`（codex 继承坏的 NODE_OPTIONS 会启动即崩）
- **一镜一次调用，绝不批量**（PNG 字节会撑爆 rollout）
- 用了 `-i/--image` 这类变长参数时 **prompt 必须走 stdin**
- 提示词里明写「copy to ./<段号>/f<切序>.png」，别让图留在 codex 默认目录
- 提示词末尾固定加：`No text, no watermark, no borders — a single clean full-bleed frame.`（分镜图是干净的一帧，不是设定图，不要格子边框）
- 单个失败跳过不阻断，最后汇总说明
- **不碰 CLI fallback**（要 `OPENAI_API_KEY`）

## 出图范围

**默认先出第一段的整套分镜图给用户看效果**（主 + 子共 3–5 张）——画风、资产一致性、正反打构图对了再往后补。一集约 30–40 格就是同样次数的调用，方向错了整批重来。用户明确说全出再全出。

## 拿到图先扫一眼

- 和场景设定图是不是同一个世界（材质、光、旧化程度）
- 角色的脸和衣服对不对得上角色设定图
- 景别对不对（提示词写 close-up 出来却是全景 → 重生成）
- 有没有多出来的人（背景围观群众是最常见污染）——多人就重生成
- 姿态是否被画面直接证明：躺/坐/站、身体支撑点、持物手和道具接触是否正确
- 前后镜头的轴线、视线、屏幕方向和人物位置是否连续
- 剧情关键信息是否达到 `information.minFrameCoverage`，并按 `coverageMetric` 明确测量 `frame-height`、`frame-width` 或 `frame-area`；竖屏手机进入 16:9 横屏时优先使用画面高度而不是宽度
- `exactText: true` 是否使用可跟踪屏幕和后期合成，而不是相信生成图里的文字

未通过任一关键检查的图片标为 `rejected`，不得写进最终 Ref2VA `references`。设置 `referenceQcRequired: true` 时，每项参考必须保存 `requiredChecks`、逐项布尔 `checks` 和 `reviewStatus: approved`。
