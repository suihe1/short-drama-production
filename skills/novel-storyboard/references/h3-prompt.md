# H3 提示词交接与模式路由

本文件不复制 MiniMax H3 的提示词手册。制作 H3 提示词时，必须使用 MiniMax 官方 `h3-prompt-writing` skill，并完整读取它为所选模式指定的参考文件。若官方 skill 不可用，只完成技术分镜并把 H3 提示词标为缺失；不得凭本文件重建一份“近似官方格式”。

需要参考媒体的模式，最终 H3 提示词后于候选素材验收；T2VA 无需凭空补参考图。先用 `frame` 生成和审核图片，再按照实际通过的文件、Picture 顺序与职责编写 `subject_definitions` 和 `retention_analysis`；不得先冻结完整 Ref2VA 文案，再接受一张姿态、手别或构图不匹配的图片。

## 1. 先选模式

在每个 segment 写明 `generationMode`：

- `h3-t2va`：无视觉/音频参考。
- `h3-i2va`：一张真实首帧，`referenceMode: first-frame`。
- `h3-fl2va`：真实首帧与尾帧，`referenceMode: first-last-frame`。
- `h3-l2va`：一张真实尾帧，`referenceMode: last-frame`。
- `h3-ref2va`：多模态全能参考，`referenceMode: multi-reference`。

模式由任务需求和实际媒体角色决定，不能因为有多张分镜图就自动选择关键帧模式。Ref2VA 的普通参考图不是时间锚点；严禁写“Picture 2 在 Shot 2 切点被完全对齐”这类无依据指令。

## 2. 给官方 skill 的结构化输入

调用 `h3-prompt-writing` 前提供：

- 总时长与每个 `[Shot k]` 的开始时刻。
- 每镜构图、人物位置、空间方位、动作变化、机位、焦段、运镜幅度/速度、光线和声音。
- 不可改写的台词及声音路线。
- 参考文件的顺序、媒体类型和唯一职责。
- 必须保持、允许变化和禁止出现的内容。

官方 skill 返回提示词后，`novel-storyboard` 只做结构与事实校验，不再把提示词重写成另一种模式。

## 3. Ref2VA 参考素材职责

优先选择最小且互补的参考集合：

1. **人物身份**：一张清楚定义脸、年龄感、发型、体态和固定配饰的角色图。
2. **场景全局方位**：一张能读懂入口、床/桌/窗、主要道具、前中后景和轴线的空间 master；不能只给局部漂亮角落。
3. **关键道具**：只有道具外观、尺度、状态或交互会影响叙事时才单独加入。
4. **动作/构图参考**：高风险可选项。只保留无法仅靠文字稳定说明、且人物肢体、持物手、支撑点、屏幕方向和轴线全部通过 QC 的视角或关键姿态；任一项不对就不用该图，改为 `referenceControlMode: semantic-assets`。
5. **屏幕内容参考**：剧情关键的视频/照片内容可独立成为全屏主观镜头素材；不要只把它缩在手机屏幕内。精确 UI 和文字走后期合成。
6. **声音/运动参考**：必须有明确的复用或参考关系，且与人物/镜头绑定。

`semantic-assets` 模式中，参考只回答“人物/环境/道具/内容长什么样”，不得把设定图的站姿、白底排版、拼版边框或展示角度复制进视频；“怎么躺、哪只手拿、从哪边拍、何时切镜”全部写入逐镜提示词。

不要把每个 cut 的截图机械地全部挂载。相近的人脸 CU/ECU、同角度重复图、仅裁切不同的图、手别/服装/场景方位互相冲突的图会造成参考竞争。发现重复时保留职责更清楚的一张，并让 `detailed_description` 完成景别变化。

Ref2VA 的六段式、任务前缀、词数与镜头标记以官方 skill 的 references/ref-en.txt 为准；本地校验器同时检查这些约束。此处不再复制第二份格式模板。

## 4. 关键帧模式

I2VA / FL2VA / L2VA 的固定首行、三段式字段、首尾帧关系和时长格式完全服从官方 `h3-prompt-writing/references/base-en.txt`。只有媒体确实承担首帧/尾帧时才能使用这些句式；普通角色图、场景图和分镜规划图不能冒充关键帧。

## 5. 共同校验

- H3 执行提示词严格按官方 skill 使用英文；中文对白放在 `<d>[Chinese] ...</d>`，可见中文文字保留原文。不要因为网关按 Unicode 字符计数就把正式三段式/六段式整体改成中文。
- 后续 `[Shot k]` 的时间戳等于前面镜头时长累计。
- 运镜写成自然英语，包含必要的类型、幅度和速度。
- 每镜明确当前构图、环境、主体位置、动作/状态变化、光线、声音和引用生效点。
- 台词、环境声和非叙事配乐不互相重复。
- 全局负向约束不能替代具体的保持项，也不能放任参考素材互相冲突。
- 使用 `referenceQcRequired: true` 时，任何 `reviewStatus` 非 `approved`、必需检查缺失或检查结果为 false 的参考不得导出。

## 6. CompShare 5000 字符预算

CompShare 统计的是“主提示词 + `promptSuffix`”的 Unicode 字符总数。不要写到 5000 临界值；主提示词建议控制在 4400–4700，给干净画面后缀和临时修订保留 200–400 字符。推荐分配：

- `subject_definitions`：450–750。只定义真实输入参考及其唯一职责；纯文字生成的临时内容不要伪装成无来源的 `<Subject N>`。
- `summary`：180–300。只写任务类型、时长、镜头链和参考/文字的控制边界。
- `retention_analysis`：450–700。记录真实参考必须保持或允许改变的属性，不复述全部外观。
- `detailed_description`：2500–3200，占总预算约 55%–65%。优先保留逐镜切点、景别/焦段、主体位置、支撑点、持物手、动作相位、信息占比、运镜触发与停点、跨镜连续性、声音事件。
- `overall_soundscape`：250–450。只写连续底噪和逐镜物理声，不重复画面。
- `non_diegetic_music`：无配乐写 `N/A`；有配乐时 50–150。

压缩顺序：先删文学性形容词、风格同义词、剧情解释和跨段重复；再合并共享光线/声场。不得优先删除物理姿态证据、屏幕方向、关键内容覆盖率、同一物体跨切对应关系或防止夸张表演的约束。具体可见关系比“保持一致”“电影感”“克制”等抽象词更值字符。

`detailed_description` 内每镜先写画面内主运动的 `setup → trigger → development → settle`，再写摄影机运动。主体、道具、环境、摄影机四层中只选一个主运动，其余最多两个低强度次运动。只写 `Push In`、`dynamic` 或 `subtle movement` 不算运动描述。节奏提速必须先改分镜秒数与 `[Shot]` 切点；正式任务不得靠成片倍速伪造。

### Context-IR 判断

MiniMax 官方建议完整 H3 工作流包含 Context-IR；由于本流程已用官方 `h3-prompt-writing` 生成结构化执行提示词，是否再次开启采用项目样片策略：

- 适合：原始输入仍偏创意 brief、自然语言重复较多，或项目运动复杂样片已经证明开启后主体/道具运动更完整。
- 谨慎：已经是官方六段式、切点精确、姿态/手别/轴线/信息覆盖率约束密集的生产提示词。Context-IR 可能把多个可见物理证据压成抽象状态，或产生修饰对象歧义。
- 开启时仍提交完整英文执行提示词，不能把关键约束交给优化器补写。中文自由 brief + Context-IR 可以单独测试，但测试语言时只能改语言，不能同时换参考集、重写镜头或改时长。返回 prompt 若与输入相同，视为输入回显；以独立视频 A/B 判断。项目样片胜出后可对同类镜头选择性开启，不自动扩展到精确文字、复杂手部或严格连续性片段。
