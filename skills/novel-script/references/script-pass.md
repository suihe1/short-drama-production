# 逐集写戏与编审

输入当前集骨架、相关人物/美术事实以及前集结尾；输出 scenes 与有序 flow。先确定人物目标、阻碍、选择及代价，再安排动作与对白。类型节奏服从项目约定，不把所有短片写成同一种强反转短剧。

## 编写与计时

- 每个动作节拍描述一个可见行动；每句对白独立记录说话人与语气。保留潜台词，不强迫身份相同的人使用同一种口吻。
- 默认单句上限 35 字、动作与对白折算由 params 决定；这些是当前工具预算。围读或临时音轨验证停顿、重叠和必要反应，再调整受支持参数和 duration。不要为满足公式填充动作，也不要机械删动作压时长。
- 超时先检查重复信息和解释性对白，保留推动因果的行动、关键证据和反应。戏不足先判断是否只是估时偏差。
- 常见动作有利于生成稳定，但复杂交互不等于必然失败。将工具接触、交接、微表情的戏剧信息写清，交导演决定拆解、插入镜头、遮挡或实测，不在编剧阶段一律删掉。
- hookBeat 在配置的 hookWindow 内落到具体节拍；抓人可以来自行动、静态证据、声音或反常关系，不能强制奔跑。独立片结尾可闭环或留余韵，连续剧按叙事需要兑现或制造悬念；默认 advisory 不把 cliff 缺失当成改写命令。
- 每场至少有可观察的行为或反应；克制对白戏不需按每两句台词机械插动作。VO 与多人场景按戏剧必要性使用，技术声音上限留给生成层核对。

## 连续性与修改

相邻场/集检查故事时间、人物知情范围、关系变化、服装伤痕、道具归属和在场者。跨集并行前先确定这些交接事实；因果未决时顺序写。改一拍连读上下文，空间跳变可用明确省略或场次转换，不强迫把所有移动写全。

意见先归并为一份修改清单，区分剧情事实、表演建议和拍法；剧情由编剧改，拍法交导演，美术新增需求交美术。修改后重新校验当前批与受影响邻集，并报告差异。不给下游静默覆盖已锁定资产。

## 自检

先核对每场是否发生有意义的变化，再跑 schema 与引用校验。技术 PASS 不代表台词可信或情绪成立；打开当前剧本报告，集中请用户审阅人物行动、台词和节奏。批准范围以当前批版本为准。
